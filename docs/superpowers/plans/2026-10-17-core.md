# `core` Module Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `core` module of `slideio-processor`: the shared type vocabulary, value types, flow interfaces, raster mask, and GeoJSON codec that every other module talks through. It ships inside the shared library `slideio-processor-data`, together with the project's build scaffolding.

**Architecture:** One CMake project. `core` is an internal OBJECT library (`slideio-processor-core`) linked into the SHARED library `slideio-processor-data`. Later plans add `config`, `storage` and `reporting` object libraries to the same shared library. Public headers live under `include/slideio/processor/core/`, sources under `src/core/`, private helpers under `src/core/detail/`, and tests under `tests/core/`. Every non-trivial class is pimpl'd, with a `std::unique_ptr<Impl>` member. No STL container and no template appears in any public signature except `std::shared_ptr`.

**Tech Stack:**
- C++17, CMake ≥ 3.21 and Conan 2.
- GoogleTest `gtest/1.17.0`, the same version as SlideIO.
- RapidJSON `rapidjson/cci.20250205` (MIT) for the GeoJSON codec and `Provenance::toJson`.
- SlideIO 2.10, found with `find_package(slideio)`. `core` uses only its enum header, in one test.

**Spec:** `docs/superpowers/specs/sds/01-core.md` (SDS 01), under the conventions of `docs/superpowers/specs/sds/00-conventions.md` (SDS 00). Physical layout comes from `docs/superpowers/specs/2026-09-28-module-structure-design.md` §4.1 and §5. Requirement IDs refer to `docs/requirements.md`.

## Global Constraints

- **Language and namespace.** C++17 (UR-BLD-2). Everything public is in `namespace slideio::processor`; modules are header directories, not nested namespaces (C-1). Private helpers go in `namespace slideio::processor::detail`, in headers under `src/core/detail/`, which are never installed.
- **Export macro.** `SLIDEIO_PROCESSOR_DATA_EXPORTS`, defined in `include/slideio/processor/core/export.hpp`:
  - `__declspec(dllexport)` when `_WIN32` and `SLIDEIO_PROCESSOR_DATA_API` are both defined;
  - `__declspec(dllimport)` on `_WIN32` otherwise;
  - `__attribute__((visibility("default")))` elsewhere.
  - Every exported class, free function and interface carries it. MSVC builds add `/wd4251 /wd4275`, as SlideIO does.
- **ABI rules (C-2, UR-API-2).**
  - No STL container, `std::string` or template in a public signature, except `std::shared_ptr`.
  - Every `enum class` is `: int32_t`.
  - No logic in headers: every definition is out of line, including trivial getters and the virtual destructors of interfaces.
  - POD structs (`Point64`, `Rect64`, `BlockPlane`, `ErrorContext`, `MeasurementBound`) are the only exemption from pimpl. Their member functions are still defined out of line.
- **Integers (C-3).** `int64_t` for every pixel count, area, coordinate, index and byte size. `int32_t` for channels, levels, layer, stage and label ids, and counts bounded by structure. No `size_t` in a public signature.
- **Strings (C-4).**
  - In: `const char*`, UTF-8. Passing `nullptr` throws `InvalidArgumentError`, unless the method documents otherwise.
  - Out, variable length: the function returns the required length, excluding the terminator. It fills and terminates the buffer when the capacity allows, and truncates but still terminates when it does not. A `nullptr` buffer queries the length.
  - File paths are UTF-8 and are opened through `std::filesystem::u8path`.
- **Collections (C-5).** Count plus indexed accessor, or fill-caller-buffer under the C-4 contract. An out-of-range index throws `InvalidArgumentError`.
- **Errors (C-6, UR-API-5).** Only `ProcessorError` subclasses cross the public boundary. Code calling RapidJSON or the standard library's I/O catches `std::exception` at the boundary and rethrows the appropriate `ProcessorError`, with the original `what()` as `cause()`.
- **Naming (C-9).** Types in PascalCase; methods and free functions in camelCase; enumerators in PascalCase; constants with a `k` prefix; headers in lower_snake. Getters have no `get` prefix.
  - **Ruling:** SDS 00 C-9 asks for this to be checked against SlideIO, which does use `getName()`. The SDS signatures across all seven modules are written without the prefix, so the spec stands and this plan follows it.
- **Thread-safety (C-7) and documentation (C-12, UR-API-7).** Every public entity has a Doxygen comment covering: its parameters, return value, the exceptions it throws, its thread-safety level, and the requirement IDs it implements.
- **Traceability (UR-QA-1).** Every test file starts with a comment line `// Requirements: UR-…, UR-…` listing the IDs its tests cover.
- **Library version.** `0.1.0`, from `project(slideio-processor VERSION 0.1.0)`.
- **Build commands on this machine.** Conan is `C:\Users\Stanislav\anaconda3\envs\conan2\Scripts\conan.exe`. Elsewhere, `conan` is on `PATH`.

```sh

cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE=build/conan/conan_toolchain.cmake \
```

- **Commits.** One commit per task, on the feature branch, with a conventional prefix (`build:`, `feat(core):`, `test(core):`). Org policy: the code is AI-generated and must be human-reviewed before it merges to `main`.

## Rulings on spec gaps

SDS 01 leaves the following open. Each ruling is binding on this plan. Each is listed for the SDS owner, to fold back into SDS 01.

| # | Gap | Ruling |
|---|---|---|
| R1 | How a `ProcessorError`'s stage, operation, cause and tile are set. SDS shows only a protected `(ErrorCode, const char*)` constructor. | A POD `ErrorContext { const char* stageName; const char* operationName; const char* cause; bool hasTile; int64_t tileX; int64_t tileY; }`, zero-initialised by default. Every subclass has a public constructor `(const char* message, const ErrorContext& context = ErrorContext())`, plus its own leading data fields where it has them. The context's strings are copied. |
| R2 | `ErrorCode::Internal` has no class. | Add `InternalError : ProcessorError`. It is used where a broken invariant or a third-party failure has no better category. |
| R3 | What `what()` contains. | `what()` gives the message, then `; stage: S`, `; operation: O`, `; tile: (X, Y)` and `; cause: C`, each only when present, in that order. |
| R4 | Implementers of `ObjectSource` cannot read an `ObjectQuery`. SDS gives it setters only. The module rules forbid sibling modules from using `core/detail`. | Add public read accessors (Task 10). Without them no `ObjectSource` can be written, including this plan's own test fakes. |
| R5 | How a record's `stage()` gets stamped. | Deferred to the `storage` plan. `core` stores the field, and `stage()` returns an invalid id until storage adds the stamping route. |
| R6 | When an id is valid. | `LayerId`, `StageId`, `LabelId` and `RasterId` are valid iff `value() > 0`. The default value is `0`. This leaves `0` free to mean "none" in a label raster, as SDS 01 §1.9 requires. |
| R7 | `ObjectId::fromAnchor` is `noexcept`, but `(y << 31) \| x` only fits `0 ≤ x < 2^31` and `0 ≤ y < 2^32`. | An anchor outside that range, or an invalid layer, gives an invalid `ObjectId`. It never wraps. |
| R8 | What a `Point64` means to `Polygon::contains`. | Vertices lie on the pixel-corner lattice, so the unit square `(0,0)-(1,1)` is pixel `(0,0)`. `contains(p)` tests the centre of pixel `p`, `(p.x + 0.5, p.y + 0.5)`, by even-odd. `boundingBox()` is `{minX, minY, maxX − minX, maxY − minY}`. |
| R9 | `Measurement::isCalibrated()` has no input. | `false` iff the unit is `Pixels` or `SquarePixels`. |
| R10 | The fill rule's precise form (§1.17). | A pixel is set iff the even-odd region has positive-area overlap with the pixel's square. Degenerate coincident edges may over-include, which is the allowed direction. |
| R11 | Which object wins when several cover one pixel in a raster source. | The smallest `ObjectId` wins, which makes the result deterministic (UR-QA-3). `Label` content uses the record's own label, because an `ObjectSource` delivers `ObjectRecord`s and the effective set is not reachable through it. Flagged for the `storage` plan. |
| R12 | Holes have no owner, but GeoJSON `MultiPolygon` needs one. | The writer gives each hole to the first outer ring, in ring order, that contains the hole's first vertex. A hole contained by none goes to the first outer ring. |
| R13 | GeoJSON geometry the reader cannot represent. | Features whose geometry is not `Polygon` or `MultiPolygon`, or is null, are skipped with a `LogLevel::Warning` message naming the feature's index and type. Malformed JSON throws `InvalidArgumentError`. |
| R14 | `dilateMask`'s structuring element. | A square `(2r+1)²`, which is the separable one. Dilation stays inside the mask's region. |
| R15 | Copy and move members SDS leaves out. | `ObjectQuery`, `MeasurementSet`, `Provenance`, `CancellationToken` and `ChannelSelection` get the full copy and move set. `Measurement` gets a default constructor. The writer and reader are move-only. |

## Review Focus

1. **An object just outside a tile that dilation brings into it.** `makeLayerMaskSource` must query and rasterise over the tile grown by the dilation radius, then dilate, then crop. Otherwise the object is missing from the mask with no trace. This is pinned in Task 13.
2. **Two adjacent masks sharing a seam.** Each must set exactly the seam pixels that one mask over their union sets, including for diagonal edges and a level scale of 4. This is pinned in Task 11.
3. **A non-ASCII UTF-8 path on Windows.** A path like `tést_日本.geojson` must write and read back; `fopen(char*)` would fail on it. This is pinned in Task 14 and Task 15.
4. **QuPath-shaped input.** A top-level array of features, a `MultiPolygon`, a duplicated closing vertex, `classification` as an object with `name`, and a `Point` feature among polygons must all import. The `Point` feature is skipped and the rest are kept. This is pinned in Task 15.
5. **Anchors outside the packable range.** Negative values, `x ≥ 2^31` and `y ≥ 2^32` must give an invalid id rather than one colliding with a real anchor. This is pinned in Task 5.

### Task 4: Geometry — `core/geometry.hpp`

**Files:**
- Create: `include/slideio/processor/core/geometry.hpp`, `src/core/geometry.cpp`, `tests/core/test_geometry.cpp`

**Interfaces:**
- Consumes: `InvalidArgumentError`.
- Produces:
  - `Point64`, `Rect64` and `Polygon`, exactly as SDS 01 §1.3.
  - Also `bool operator==(Point64, Point64) noexcept` and `bool operator==(const Rect64&, const Rect64&) noexcept`, both exported and both defined out of line. Later tests need them.

Pinned semantics:
- **`Rect64`.** `isEmpty()` is `width <= 0 || height <= 0`. `contains(p)` is half-open: `x ≤ p.x < right()` and `y ≤ p.y < bottom()`. `intersects` is false for rectangles that only touch, and for any empty rectangle. `intersected` of disjoint rectangles is `{0,0,0,0}`. `united` ignores an empty operand, and two empty operands give `{0,0,0,0}`. `area()` is `width * height` in `int64_t`.
- **`addRing`.**
  - Throws `InvalidArgumentError` for: `points == nullptr`; fewer than 3 points after dropping a closing point equal to the first; or `isHole == true` while the polygon is empty, since ring 0 is always outer.
  - A last point equal to the first is dropped.
- **`ringIsHole`, `ringPointCount`, `ringPoints`.** Throw `InvalidArgumentError` for an index outside `[0, ringCount())`. `ringPoints` follows C-5.
- **Area, perimeter, centroid.** `area()` is Σ|outer| − Σ|hole|, by the shoelace formula, accumulated in `double`, with coordinates taken relative to each ring's first vertex. `perimeter()` is the length of every ring summed. `centroid()` is the area-weighted centroid, with outer rings positive and holes negative, rounded by `llround`. When `area() == 0` on a non-empty polygon, it is the rounded mean of ring 0's vertices.
- **Anchor and bounding box.** `anchor()` is the vertex with the smallest `y`, ties broken by the smallest `x`, over all rings. An empty polygon gives `anchor()` and `centroid()` of `{0,0}` and `boundingBox()` of `{0,0,0,0}`.
- **`contains(p)`.** Per R8: the even-odd test at `(p.x+0.5, p.y+0.5)`, counting an edge when `(y1 <= yc) != (y2 <= yc)`.

  - The private kernel:

```cpp
namespace slideio::processor::detail {
struct PixelGrid { double originX, originY, pixelW, pixelH; int64_t width, height; };  // level-0 space
/// Calls row(y, x0, x1) for each maximal run [x0, x1) of covered pixels in row y.
void forEachCoveredSpan(const Polygon&, const PixelGrid&,
                        const std::function<void(int64_t y, int64_t x0, int64_t x1)>& row);
}
```

Pinned:
- **Constructor.** `RasterMask(region, level, scale)` throws `InvalidArgumentError` for an empty region, `level < 0`, or a `scale` that is not finite and `> 0`. Every pixel starts at 0, and a set pixel is `255`.
- **`row(y)`.** Throws for `y` outside `[0, height)`.
- **`test(p)`.** Uses absolute level coordinates; false outside the region.
- **`testLevel0(p)`.** Tests the pixel `(floor(p.x / scale), floor(p.y / scale))`.
- **`rasteriseInto(mask, polygon)`.** Uses the grid `{region.x*scale, region.y*scale, scale, scale, region.width, region.height}` and sets every covered pixel. It is additive.
- **Coverage algorithm (R10).** The rule and test-tie conventions are pinned here; implement exactly this.
  1. Map vertices into pixel units, `u = (x − originX) / pixelW` and `v = (y − originY) / pixelH`, and clip each edge to the grid box.
  2. Mark every pixel whose **open** interior a clipped edge passes through, walking the edge with the Amanatides–Woo traversal.
     - A segment lying exactly on a pixel boundary line marks nothing.
     - A segment touching only a pixel corner marks nothing.
  3. For each row, find the crossings of every edge with the line `v = y + 0.5`, counting an edge when `(v1 <= vc) != (v2 <= vc)`. Sort them, and fill the pixels whose centre `u = x + 0.5` lies between crossings 2k and 2k+1.
  4. Emit the union of steps 2 and 3 as runs.
- **Conformance with `Polygon::contains`.** Over the grid of level 0 with scale 1, every pixel `p` with `polygon.contains(p)` is covered. For a polygon whose vertices are all integers, the covered set equals the `contains` set exactly.

### Task 15: GeoJSON reader — `core/geojson.hpp` (part 2)

**Files:**
- Modify: `include/slideio/processor/core/geojson.hpp`, adding `GeoJsonReader`.
- Create: `src/core/geojson_reader.cpp`, `tests/core/test_geojson_reader.cpp`

**Interfaces:**
- Consumes: `Polygon`, `logMessage` (Task 9), `IoError`, `InvalidArgumentError`, and `uniqueTempPath`/`readFile` (Task 14).
- Produces: `GeoJsonReader`, as in SDS 01 §1.14, move-only.

Pinned:
- **Streaming.** The reader pulls with `rapidjson::Reader::IterativeParseNext`, using `kParseNumbersAsStringsFlag`, over a buffered stream on an `std::ifstream` opened through `u8path`. It feeds a SAX handler, which is a state machine over the key path. `next()` pumps tokens until one feature is complete or the document ends. Only the current feature is held in memory.
- **Accepted top-level shapes.** A `FeatureCollection` object (its `features` array; other keys skipped), an array of `Feature` objects, or a single `Feature`.
- **Geometry.**
  - `Polygon` gives its first ring as an outer ring and the rest as holes.
  - `MultiPolygon` gives, for each polygon, its first ring as an outer ring and the rest as holes.
  - Coordinates are parsed with `strtod`, then `llround`.
  - Anything else, or a null geometry, is skipped with a Warning (R13).
- **Classification.** `classification()` is `properties.classification.name` when the value is an object, the string itself when it is a string, and `""` otherwise. `layerName()` is `properties.layer` as a string, or `""`.
- **Properties.** They are, in document order:
  - every top-level scalar property other than `classification` and `layer`;
  - then every scalar entry of `properties.measurements`, named `measurements.<key>`.
  - Values are text: strings raw, numbers as written in the source, booleans `true` or `false`. Nulls and nested objects are skipped. `propertyName` and `propertyValue` follow C-5.
- **Accessor lifetime.** Returned pointers are valid until the next `next()`.
- **Counting.** `featuresRead()` counts the features returned.
- **Errors.**
  - A file that cannot be opened throws `IoError` naming the path.
  - A parse error throws `InvalidArgumentError` with the path, the byte offset and RapidJSON's error text (`GetParseError_En`).
  - A ring with fewer than 3 distinct points throws `InvalidArgumentError` naming the feature's index.
  - Accessors called before the first successful `next()` return empty values.
