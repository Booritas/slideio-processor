# `storage` Module Implementation Plan C: rasters and the v1 format freeze

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the `storage` module of `slideio-processor`. This plan adds persisted rasters (`RasterDeclaration`, `RasterWriter`, `RasterRegistry`), their `rasters` table and journal events, and the sweep `Workspace::open` needs. It then freezes store format v1.

**Architecture:**
- **This is plan C of three.** Plans A and B are merged before it starts. B gave `Store` its `edges()` and `annotations()` accessors. C adds `rasters()` and uses nothing else of B.
- **Raster pixels live in standard tiled pyramidal BigTIFF files beside the store, not inside it** (SDS 03 §3.8). The store holds one row per raster, naming the file. The files are written and read with **libtiff directly**, linked PRIVATE into `slideio-processor-storage`. SlideIO and OpenCV are not used (S40).
- **Writing never holds a slide-sized buffer.**
  - `writeTile` cuts each incoming `BlockView` into fragments aligned to the TIFF tile grid. It compresses each fragment and appends it to a spool file.
  - `flush` builds level 0 of the TIFF from the spool, one grid tile at a time. It then builds each coarser level by reading back the level above it.
  - Only after the file is closed does `flush` commit the row that makes the raster readable. This is SDS 03 §3.8's non-transactional protocol.
- **The new code is a few `detail` units with one job each:**
  - `tiff_io`: opens a libtiff handle and turns libtiff errors into exceptions;
  - `tile_spool`: holds the fragments;
  - `pyramid_tiff_writer`: builds the TIFF file;
  - `tiff_raster_reader`: reads a tile at any scale.
  - The public `RasterWriter` and `RasterRegistry` connect these units to `StoreImpl`, using the same mechanisms as plan A: `StoreGate`/`GateClient`, `withWriteTransaction`, `appendEvent` and `notifyCommitted`.
- **The format is frozen at the end** (S53). A schema snapshot and a golden store are checked in, and every later build must still open the golden store.

**Tech Stack:**
- C++17, CMake ≥ 3.21, Conan 2 and SQLite, as before.
- New: `libtiff/4.7.1`, which brings in `zlib` (S40). The spool uses zlib directly.

**Spec:** `docs/superpowers/specs/sds/03-storage.md` (SDS 03): §3.8, the `rasters` row of §3.12, the `Raster*` kinds of §3.1, and §3.9 for `Event`. | # | Gap | Ruling |
|---|---|---|
| S40 | Raster I/O library (**user decision, binding**). | Raster TIFF I/O uses **libtiff directly**, never SlideIO and never OpenCV. The installed SlideIO DLLs embed OpenCV statically, so linking them would put OpenCV into the viewer's data library, against design 5.1. **Version:** Conan `libtiff/4.7.1`, or the newest 4.7.x ConanCenter carries if that one is absent (Task 1 states which). It is a current 4.7 release, and it has `TIFFClientOpenExt` and `TIFFOpenOptions` (4.5+). SlideIO pins 4.6.0, but both copies are static and private, so they need not match, and 4.7.x carries libtiff's later security fixes. **Recipe options:** `zlib` on; `jpeg`, `jbig`, `lzma`, `zstd`, `webp`, `lerc`, `libdeflate` and `cxx` off; all set in `configure()`. It is linked into `slideio-processor-storage` PRIVATE as `TIFF::TIFF`, together with `ZLIB::ZLIB`. SDS 03 §3.8's paragraphs saying the module gains a dependency on SlideIO are amended in Task 8. |
| S41 | File layout. | **BigTIFF, always.** One layout is simpler than switching at 4 GB, and every target reader handles BigTIFF. **Tiled, 512×512.** **Multi-page reduced-resolution, not SubIFDs:** page 0 is full resolution, and page *k* has `NewSubfileType = FILETYPE_REDUCEDIMAGE` and half the size of page *k−1*, rounded up. This is GDAL's and COG's internal-overview layout, which GDAL-based readers (SlideIO's GDAL driver among them) understand. **`PLANARCONFIG_SEPARATE`**, with one TIFF sample per plane, matching `BlockView`'s planar layout, so no interleaving is needed. **Tags:** `PHOTOMETRIC_MINISBLACK`; `SamplesPerPixel = planeCount`; `ExtraSamples` = `planeCount − 1` × `EXTRASAMPLE_UNSPECIFIED`. `BitsPerSample` and `SampleFormat` come from `DataType`: `UINT` for Byte, UInt16, UInt32 and UInt64; `INT` for Int8, Int16, Int32 and Int64; `IEEEFP` for Float16, Float32 and Float64. **Every tile of every page is written.** A tile no fragment touched is written as zeros, and its compressed bytes are encoded once per page and reused (`TIFFWriteRawTile`), so no reader meets a sparse tile. Page 0's `ImageDescription` is one JSON object: `{"slideioProcessorRaster":1,"name":…,"description":…,"dataType":"<dataTypeName>","level":L,"scaleX":sx,"scaleY":sy}`. |
| S42 | Compression and predictor. | `RasterCompression::None` → `COMPRESSION_NONE`, no predictor. `Lzw` → `COMPRESSION_LZW`, and `Deflate` → `COMPRESSION_ADOBE_DEFLATE` at zlib level 6. Both use a predictor: `PREDICTOR_HORIZONTAL` for every integer type; `PREDICTOR_FLOATINGPOINT` for Float32 and Float64; none for Float16, whose floating predictor GDAL does not read reliably. |
| S43 | Pyramid. | Pages are added until both dimensions are ≤ 512. Each page is built from the one above it: 2×2 blocks to 1. Edge blocks have 1 or 2 samples present. **Integer types take the top-left sample present** (nearest), so label, anchor and class values are never invented, and an `Int64` anchor survives exactly. **Float types take the mean of the samples present**, computed in `double`; Float16 goes through a `detail` half↔float conversion. The rule is decided by sample type alone, because the declaration carries no semantics. A continuous Byte map gets nearest too, which loses smoothness and never correctness. |
| S44 | Where the files live, and their names. | The directory is `<store path>-rasters/`: the store path with `-rasters` appended, as with `-wal`, `-shm` and `-writer.lock`. Two stores in one directory, as every test has, therefore never share one. It sits inside the workspace directory, because the store does, so UR-STG-9's directory unit holds. It is created on the first `writerForStage`. File names are 32 random hex digits (`std::random_device`, as for `store_uuid`), with `.tif` for a raster and `.spool` for its spool. The row stores the **file name only**, never a path, so a moved or copied workspace still resolves. |
| S45 | Level and geometry of written tiles. | The first accepted tile fixes the raster's level: `writtenAtLevel = view.level()`, `scaleX = slideRect().width / width()` and `scaleY = slideRect().height / height()`. These follow SDS 01 §1.17: the scale is read from the view's integers, not from a level index. Every later tile must have the same `level()`, and its extent must agree with that scale to within one level pixel: `|slideRect().width − width·scaleX| ≤ scaleX`, and likewise for y. Clipped edge tiles therefore pass. The tile's origin in level pixels is `llround(slideRect().x / scaleX)`, rounded to the nearest pixel as `rasteriseInto` does. The raster's extent is the maximum of `origin + width` (and of `origin + height`) over the written tiles, with its origin at (0, 0). Area beyond the extent reads as zero, as unwritten area does. `writeTile` throws `InvalidArgumentError` naming the field for: a null view; a plane count other than the declared one; a plane type other than the declared one; a level other than the first tile's; a scale outside the tolerance; a negative origin; or an extent beyond 2³¹−1. |
| S46 | Accumulation and memory. | `writeTile` cuts the view along the 512 grid into fragments. Each fragment is (grid column, grid row, rectangle within the tile, planes). The fragments are compressed with zlib level 1 outside any lock, then appended to the `.spool` file under the writer's mutex, which also guards a memory-resident index entry (`detail::SpoolEntry`, about 48 bytes per fragment). `writeTile` is therefore ThreadSafe, and compression runs in parallel. When fragments overlap, the later spool append wins. The pipeline writes disjoint tiles; overlap is the caller's misuse, never corruption. At `flush`, memory is one level-0 tile per plane plus the fragment decode buffer, then four source tiles and one output tile per pyramid step. None of this is charged to `MemoryBudget`, which `storage` does not hold. |
| S47 | Writer lifecycle and the publish protocol. | **One live writer per raster.** A live writer is one that has not been flushed or destroyed. `writerForStage` throws `InvalidArgumentError` when the raster already has a live writer, or when `isPopulated` is true for a stage other than `stage`. It also throws for an unknown stage or raster, and `IoError` on a `ReadOnly` store. **It appends no event and opens no transaction:** S48 moves `RasterDeclared` to `declare`. It only allocates the generated name and opens the spool. **`flush`** runs in order: compose and write the TIFF (S41–S43); close it; `fsync` it; delete the spool; then one write transaction. That transaction sets the row's `writer_stage_id`, `level`, scales, `width`, `height`, `file_name`, `bytes` (the file's size) and `populated = 1`, and appends `RasterWritten`; `notifyCommitted` follows. When the same stage re-runs a populated raster, the old file is deleted **after** that commit, so a reader never sees the row point at nothing. `flush` is terminal: a second `flush` is a no-op, and `writeTile` after `flush` throws `InvalidArgumentError`. A `flush` with zero tiles deletes the spool, publishes nothing and appends no event. If `flush` fails, it deletes its partial files where it can, leaves the row untouched, and rethrows. **The destructor never publishes.** It deletes the spool and any partial TIFF, and logs at `Warning` when tiles were abandoned. A stage that fails must leave a declared, unpopulated raster (SDS 04 §4.4), so publishing from a destructor would be wrong. The writer holds the `StoreGate`. Its `GateClient::flushBeforeClose` **abandons** the same way, so `Store::close` never builds a pyramid. After close, every writer call throws `IoError` with `store is closed`. |
| S48 | Declarations and registry reads. | `declare` validates and throws `InvalidArgumentError` for: a null or empty name; a duplicate name (rasters have their own namespace, compared exactly); `DataType::Unknown` or an out-of-range type; a `planeCount` outside 1..65535 (the TIFF `SamplesPerPixel` limit); or an unknown compression. It inserts the row and appends `RasterDeclared` in one transaction. `RasterDeclaration` is pimpl'd, with the full copy and move set; its constructor and setters never validate. Read-only getters are added: `name()`, `planeType()`, `planeCount()`, `compressionValue()` and `descriptionText()`. These names avoid colliding with the SDS's fluent setters. Ids number from 1. `name`, `planeType`, `planeCount`, `writerStage`, `writtenAtLevel` and `at` throw `InvalidArgumentError` on an unknown id or index. **`isPopulated` is the row's flag AND the file exists** (`std::filesystem::exists` with `error_code`, so it stays `noexcept`). Copying the store file without its `-rasters` directory therefore yields declared, unpopulated rasters, exactly as SDS 03 §3.8 states. `writerStage` and `writtenAtLevel` throw `InvalidArgumentError` when the raster is not populated. `bytesOnDisk` is the row's `bytes` when populated, and 0 otherwise. `totalBytesOnDisk` sums it. Closed and read-only behaviour follows S2. |
| S49 | Raster events. | `events` gains a nullable `raster_id INTEGER` column, and `detail::EventRow` gains `int32_t rasterId`. `Event` gains `RasterId raster() const noexcept;`, which is invalid for non-raster kinds and for a moved-from event. The fields per kind: **`RasterDeclared`** carries the raster. **`RasterWritten`** carries the raster, the stage, `objectCount` = tiles written, and `boundingBox` = the union of the written tiles' level-0 `slideRect`s. **`RasterDropped`** carries the raster and the stage that had written it. The `types.hpp` comment on `RasterWritten` changes from "A raster block was written" to "A raster was published". |
| S50 | `sourceFor`. | An unknown raster throws `InvalidArgumentError`. An **unpopulated** raster returns a source that fills zeros. The source is bound to the file named in the row at the moment `sourceFor` is called; it does not follow a later re-run. `planeType()` and `planeCount()` are the declared ones. `fillTile(view)` throws `InvalidArgumentError` unless the view has exactly `planeCount()` planes of `planeType()` and a derivable scale. **Page choice:** let `t = min(slideRect().width / width(), slideRect().height / height())`. Take the coarsest page *k* with `scaleX·2^k ≤ t·(1 + 1e-9)`, or page 0 when none qualifies (the view is finer than the raster was written). **Sampling** is nearest. The level-0 centre `x0 + (i + 0.5)·tx` maps to page pixel `floor(centre / (scaleX·2^k))`, and likewise for y. Pixels outside the page's extent read 0. The view's `level()` number is ignored; only its geometry counts. A source is ThreadSafe. It keeps a pool of read handles, one per concurrent caller, opened on demand; each call caches the TIFF tiles it decodes. A file that vanished after `sourceFor` makes `fillTile` throw `IoError` naming the file. |
| S51 | Discard, and the sweep `Workspace::open` needs. | `discardRasterOfStage(StageId)`. An unknown stage throws `InvalidArgumentError`, and a `ReadOnly` store throws `IoError`. For each raster whose row `writer_stage_id` equals `stage`, ascending by id, in **one** transaction: clear `populated`, `file_name`, `bytes`, `level`, scales, `width`, `height` and `writer_stage_id`, and append one `RasterDropped` per raster. Then commit and notify. The files are deleted **only after the commit**. A deletion that fails (on Windows, a file still open in a live source) logs at `Warning` and leaves an orphan for the sweep. A stage with no raster is a no-op with no event. A live writer of that stage is unaffected; its later `flush` publishes as usual. **New:** `const char* RasterRegistry::directory() const noexcept;` returns the S44 directory as UTF-8, and is valid while the store lives. **New:** `int64_t RasterRegistry::removeUnreferencedFiles();` deletes every regular file in `directory()` whose name matches `^[0-9a-f]{32}\.(tif\|spool)$`, is not the `file_name` of any row, and is not owned by a live writer of this store. It returns the bytes reclaimed. Other names are never touched. A missing directory returns 0. A file that fails to delete is logged at `Warning` and not counted. It throws `IoError` on a `ReadOnly` or closed store. `Workspace::open` calls it beside its scratch clear, and reports the result (SDS 04 §4.1). |
| S52 | libtiff errors and I/O. | Every handle is opened through `TIFFClientOpenExt`, over our own `std::FILE*`. The path goes through `std::filesystem::u8path`; Windows uses `_wfopen` with the default share mode, so a read handle can run beside the write handle during the pyramid read-back. This keeps non-ASCII paths working (C-4) on every platform. Each handle has its own error context: `TIFFOpenOptionsSetErrorHandlerExtR` and `TIFFOpenOptionsSetWarningHandlerExtR`, with `user_data` pointing at a per-handle collector. The handlers return 1, so libtiff's global handlers are never reached. Errors are appended to the collector's message. Warnings go to `logMessage(LogLevel::Debug, …)`. Once per process (`std::call_once`), `TIFFSetErrorHandler(nullptr)` and `TIFFSetWarningHandler(nullptr)` silence our private copy's globals; they cannot reach SlideIO's copy. When a libtiff call fails, the caller throws `IoError` naming the operation and the file, with the collected text as the cause (C-6). There is no shared mutable state, so handles on different threads never interfere. |
| S53 | Freezing format v1. | Two checked-in fixtures, under `tests/storage/data/`. **(1) A schema snapshot,** `store-v1.schema.sql`. It holds `type\|name\|tbl_name\|sql` of every `sqlite_master` row, ordered by `type, name`, then the sorted list of `meta` keys. A test compares a fresh store against it. On any difference, it writes the actual dump beside the build and fails, saying `store format v1 is frozen: a schema change needs format_version 2 and a migration (SDS 03 §3.12)`. This catches drift in new stores, including additive drift. **(2) A golden store,** `store-v1.golden.store` plus its `store-v1.golden.store-rasters/`. It is a few hundred kB, built by a disabled generator test. A test copies it to a temp directory, opens it `ReadOnly` and `ReadWrite`, and reads back known content. This catches a change that would leave stores already written by v1 unreadable. Both are needed: the snapshot cannot prove that old files still open, and the golden file cannot see a new table. `storeFormatVersion()` stays 1. |
| S54 | Does a test open a raster in SlideIO? | **No.** Today nothing in this project links SlideIO: `build.sh` installs it for its headers only. A SlideIO test would need its DLLs deployed beside the test binary, which is not cheap. Compatibility is pinned structurally instead (Task 3): a raw libtiff read checks every tag S41 names. The first SlideIO open of a persisted raster belongs to the first test executable that already links SlideIO (`workspace` or `reporting`). Task 8 records that in traceability. |

## Review Focus

1. **A process that dies after writing tiles, before `flush` commits.** The raster must read as declared and unpopulated, never as half-written. On the next `removeUnreferencedFiles`, the spool and any partial `.tif` must be reclaimed, and the bytes reported (S47, S51). This is pinned in Task 6, using a helper process that exits with `std::_Exit`.
2. **Eight threads calling `writeTile` at once, with 1000×1000 pipeline tiles that straddle the 512 grid.** Every pixel of the result must equal the reference image exactly, and `tilesWritten` must equal the number of calls (S46). This is pinned in Task 4.
3. **Extents that are not multiples of 512 or of 2: 1×1, 513×1, 1025×777.** Page dimensions must round up, and edge blocks must average only the samples present (floats) or take top-left (integers). An `Int64` value of 2⁶²+1 must survive every page exactly (S43). This is pinned in Task 3.
4. **A read at a scale the raster was not written at, over a region partly outside its extent.** Inside the extent the result is nearest; outside it is zero. Asking finer than the written level up-samples from page 0 rather than failing (S50). This is pinned in Task 5.
5. **A discard or re-run while a source still holds the old file open on Windows.** The commit must succeed. The failed delete is logged, not thrown. The open source must keep reading the old pixels, and the sweep must reclaim the file once the source is gone (S47, S51). This is pinned in Task 6.
