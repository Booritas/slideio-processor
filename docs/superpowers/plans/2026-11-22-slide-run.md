# Slide Run Implementation Plan (Python bindings, project 1)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The C++ changes the Python bindings need:
- operations can say their results may vary between runs;
- the run reports how many objects a label-image operation had to drop;
- a `LabelImageOperation` base turns a model's per-tile label image into complete objects;
- a pipeline file describes a whole slide run (layers, rasters, stages, exports);
- `SlideRun` executes a pipeline file against one slide;
- a workspace can be created or opened from a SlideIO scene that is already open;
- no error message, error cause or log line carries a file path.

**Architecture:**
- The determinism flag and the drop count extend the existing pipeline and workspace modules.
- `LabelImageOperation` lives in `algorithm`, next to `segment.contours`, and reuses its labelling and tracing helpers.
- `PipelineFile` and `SlideRun` live in a new engine module, `run`. It depends on `workspace`, `masks`, `pipeline` and the data library, and resolves operations by name through `OperationCatalog`, never by linking `algorithm`.

**Tech Stack:** C++17, CMake, rapidjson (already used by `workspace`), GoogleTest.

**Spec:**
- `docs/superpowers/specs/2026-11-22-python-bindings-design.md` §4 (this plan), §2 D4–D6, §8 (what must stay possible).
- `docs/superpowers/specs/sds/04-workspace.md` (stage record, `StageRunner`), `05-pipeline.md` (operations, anchors), `07-reporting.md` (exports).
- `docs/superpowers/specs/2026-09-28-module-structure-design.md` §4–5 (module graph).
- Requirements: UR-EXT-1, UR-EXT-3, UR-EXT-4, UR-EXT-5, UR-RES-11, UR-QA-3, UR-SEG-4.

**Base:** branch `feat/slide-run` from `docs/python-bindings-design` (f45a194 or later), which is `main` 3d8b422 plus the design.

## Global Constraints

  - Tests: `./run-tests.sh -c release`; all must pass.
  - One test: `ctest --test-dir build -C Release -R <name>`.

  - No-seams check: `./build.sh --skip-slideio --no-test-seams --warnings-as-errors`, then `scripts/check-no-test-seams.sh build-noseams`.
- Zero compiler warnings and zero Doxygen warnings. A clean Windows build is not enough: GCC 14 and Clang only run in CI, so the branch must be green in CI before it is merged.
- **Library split:**
  - The data library still links no `slideio::` target and no OpenCV; the existing configure checks keep passing.
  - `run` is an engine OBJECT library. It depends on `workspace`, `masks`, `pipeline` and the data library, and never on `algorithm`. Add a configure check like the existing ones that fails if it links `slideio-processor-algorithm`.
- **Store format v2 is unchanged.** The only record change is an optional key, written only when it has content (Task 1). Existing records stay byte-identical, and the v1 and v2 golden stores pass unchanged.
- **Public API (UR-API-2):** no templates or STL containers in exported signatures. New classes use pimpl and count-and-index accessors, as `StageDefinition` does.
- **Messages:**
  - They may name pipeline-file entities: a stage, layer, raster, operation, parameter key or export kind.
  - They never carry parameter values, coordinates, pixel values, file paths or slide names.
- **UR-QA-3:**
  - A deterministic `LabelImageOperation` gives the same objects (ids, geometry, measurements) for tile sizes {512, 1024} and workers {1, 4}.
  - Two `SlideRun`s of the same file over the same slide give byte-identical CSV and GeoJSON exports.
- **Requirements lines and traceability:** every new source and test file starts with its `// Requirements: ...` line, and `docs/traceability.md` lists every new test.

## Decisions

1. **Determinism flag.**
   - `virtual bool OperationFactory::isDeterministic() const` returns `true` by default.
   - `bool OperationCatalog::isDeterministic(const char* name) const` throws `InvalidArgumentError` for an unregistered name, as the other per-name queries do.
   - When `StageRegistry::declare` builds the record (`detail::stageRecordJson`), it adds `"nondeterministicOperations": [names]`, listing every operation of the stage's pipeline that is registered and not deterministic, in pipeline order. The key is written only when that list is not empty.
   - An operation unregistered at declare time counts as deterministic; `SlideRun` registers and validates before declaring (decision 5).
   - The key is not part of `sameDeclaration`, so it never makes a stage stale.
   - `bool StageRegistry::isDeterministic(StageId) const` is false when the stored record has that key. The record parser ignores unknown keys already; keep it that way.
2. **Truncated-object count.**
   - `void OperationContext::countTruncatedObjects(int64_t count)` adds to a per-run total; a negative count is `InvalidArgumentError`.
   - The executor sums the totals over all tiles and workers.
   - `int64_t Pipeline::truncatedObjectCount() const noexcept` is valid after `runInto` and is 0 before.
   - `int64_t StageRunner::truncatedObjects() const noexcept` holds the last `run()`'s count and is 0 before.
3. **`LabelImageOperation`** (`include/slideio/processor/algorithm/segment/label_image.hpp`; engine export).
   - It is an abstract `Operation`. A subclass implements `virtual void predictLabels(const OperationContext& context, BlockView& labels) = 0`:
     - `labels` is one `Int32` plane over the halo rect, zero-filled, owned by the base;
     - the subclass writes a label per pixel, with 0 as background;
     - values only need to be distinct within the call.
   - It also implements `name()`, `halo()` and `parameters()`, as every operation does.
   - **Defaults it provides:**
     - `arity()` is `Joint`, `requiresUniformTypes()` is false, and `supportedTypes()` is every type;
     - `outputType()` is `Int32` and `outputPlaneCount()` is 1;
     - `producesObjects()` is true;
     - `workingSetBytesPerLevelPixel()` covers the halo-sized label plane plus the labelling and tracing figures `segment.contours` declares (reuse `detail/working_set.hpp`).
   - **`apply()`:**
     1. Calls `predictLabels`.
     2. Labels each maximal 4-connected set of one non-zero value as one region, with `detail::labelRegions` over the halo buffer.
     3. Traces the regions with `detail::traceRegions`, mapping points from the halo rect's origin.
     4. For each region, takes its anchor: the first point of its first outer ring, its topmost-then-leftmost vertex, which is the point `ObjectId::fromAnchor` uses.
     5. Keeps a region only when its anchor lies in the half-open `tileRectAtLevel()`.
     6. Drops a kept region that touches a side of the halo rect lying strictly inside the level, and counts it with `countTruncatedObjects`. A side that coincides with the level's own edge does not count: an object there is complete.
     7. Emits every other kept region as one complete object through the context's object sink, never as a seam fragment. It gets the geometry measurements `segment.contours` gives (`area`, `perimeter`, and their calibrated forms).
     8. Writes the predicted labels, cropped to the tile, into the output plane.
   - Extend `detail/region_emit` with a variant that emits a chosen subset of regions whole from a given origin; do not copy its body.
4. **Pipeline file** (`include/slideio/processor/run/pipeline_file.hpp`; class `PipelineFile`, copyable, pimpl).
   - **JSON layout:**
     ```json
     { "formatVersion": 1,
       "requires": ["mylab.models"],
       "layers":  [ { "name": "tissue" },
                    { "name": "nuclei", "parent": "tissue", "kind": "semantic" } ],
       "rasters": [ { "name": "prob", "type": "Float32", "planes": 1, "compression": "Deflate" } ],
       "stages":  [ <stage record, the stageRecordVersion 1 form of SDS 04> ],
       "exports": [ { "kind": "csv", "file": "nuclei.csv", "layer": "nuclei", "measurements": ["area"] },
                    { "kind": "geojson", "file": "nuclei.geojson", "layer": "nuclei" },
                    { "kind": "labelMask", "file": "nuclei-mask.tif", "layer": "nuclei" },
                    { "kind": "rasterTiff", "file": "prob.tif", "raster": "prob" } ] }
     ```
   - **Field defaults:**
     - a layer's `parent` defaults to the pixel layer and its `kind` to `"semantic"`; the other kind is `"primitive"`;
     - a raster's `compression` defaults to `RasterDeclaration`'s default;
     - a CSV export without `measurements` exports all of them, using `ColumnSchema::standard().allMeasurements()`.
   - **Members:**
     - `static PipelineFile fromJson(const char*)` and `static PipelineFile load(const char* path)`;
     - `int32_t toJson(char*, int32_t) const`, sized the way `PipelineSpec::toJson` is;
     - builders `require(const char* module)` and `addExport(const ExportSpec&)`;
     - count-and-index readers for requires, layers (name, parent name or null, kind), rasters (a `RasterDeclaration`), stages (name, record JSON) and exports;
     - `static PipelineFile fromWorkspace(Workspace&)`, which takes every non-pixel layer, every raster and every stage record from a development workspace.
   - **`ExportSpec`:** copyable, pimpl. It has `kind()` (`enum class ExportKind { Csv, GeoJson, LabelMask, RasterTiff }`), `file()`, `layer()`, `raster()` and measurements by count and index. It is built through named constructors per kind.
   - **Refused by `fromJson`, with `InvalidArgumentError`:**
     - a wrong `formatVersion`, a missing or mistyped member, or an unknown export kind;
     - duplicate layer, raster, stage or export-file names (export files compared case-insensitively);
     - a stage whose `pipeline` does not parse with `PipelineSpec::fromJson`;
     - an export `file` that is empty, `.`, `..`, or contains `/`, `\` or `:`;
     - an export naming a layer or raster the file does not declare and no stage writes.
   - Round trip: `fromJson(toJson(x))` gives an equal file.
5. **`SlideRun`** (`include/slideio/processor/run/slide_run.hpp`; ThreadConfined; pimpl).
   - **Members:**
     - `SlideRun(const PipelineFile&, const char* slidePath, int32_t sceneIndex, const char* workspacePath, const char* exportDirectory, const Configuration&)`;
     - `SlideRun& progress(ProgressObserver*)` and `SlideRun& cancellation(const CancellationToken&)`;
     - `SlideRunResult run()`.
   - **`run()`, in order:**
     1. **Validate operations.** For every operation of every stage: if `OperationCatalog::contains` is false, throw `InvalidArgumentError` naming the first missing one; then `create(name, parameters)`, whose errors propagate. Nothing has been created yet.
     2. **Open or create the workspace.** An existing `workspacePath` is opened with `Workspace::open`. A workspace whose slide is not `std::filesystem::equivalent` to `slidePath`, or whose scene index differs, is refused with `InvalidArgumentError("…the workspace belongs to another slide or scene")`, and nothing is written. Otherwise `Workspace::create`.
     3. **Declare layers and rasters.** An existing one of the same kind and parent, or the same type and plane count, is reused; a different one is `InvalidArgumentError` naming it. Then declare every stage through `detail::stageFromRecord` and `StageRegistry::declare`.
     4. **Run stages.** Repeatedly run the first stage, in file order, that is not Complete or is stale and is runnable. When stages still need running but none is runnable, throw `StageError` naming the stage and its `runBlocker`.
     5. **Write exports.** Create `exportDirectory` if needed. Write each export to `<file>.partial` in it, then rename it onto `<file>`. The kinds map as follows:
        - CSV → `CsvWriter`;
        - GeoJSON → `GeoJsonExporter`;
        - label mask → `rasteriseLabels` over the scene's full level-0 rect, then `MaskWriter`;
        - raster TIFF → `RasterTiffWriter` over `rasters().sourceFor(id)`, for the whole scene, at the scale of the level it was written at (`writtenAtLevel`, from the scene's level info).
   - **Progress and cancellation:** both are forwarded to every `StageRunner` and writer. Cancellation throws `CancelledError` and leaves no `.partial` file. A completed export file from an earlier run survives.
   - **`SlideRunResult`** (copyable, pimpl) has count-and-index accessors:
     - per stage, in file order: name, whether it ran, objects written, truncated objects;
     - per export: file name and bytes.
   - Workspace stages that are not in the file are left alone.
6. **Workspace from an open scene** (`workspace/workspace.hpp`).
   - Two new overloads:
     - `static WorkspacePtr create(const char* workspacePath, std::shared_ptr<slideio::Scene> scene, const char* slidePath, int32_t sceneIndex, const Configuration&)`;
     - `static WorkspacePtr open(const char* workspacePath, std::shared_ptr<slideio::Scene> scene, int32_t sceneIndex, const Configuration&)`.
   - Both use the given scene and never open the slide file again. `scene()` returns that same object.
   - **Checks, before anything is created or written** (each failure is `InvalidArgumentError`):
     - the scene is not null and `sceneIndex` is not negative;
     - for `create`, the scene's `getFilePath()` is `std::filesystem::equivalent` to `slidePath`;
     - for `open`, the scene's file path is equivalent to the workspace's recorded slide path, and `sceneIndex` equals its recorded scene index.
   - **What is trusted:** the caller's `sceneIndex`, which a `slideio::Scene` cannot confirm. The headers say so.
   - Provenance, the store and every later behaviour are those of the path overloads, so a workspace created either way reopens either way.
   - The new messages carry no paths.
7. **No paths in errors or logs.** About 60 sites in the library put a file path into an exception message, an error's cause, or a log line. Slide file names often carry patient identifiers, and the bindings' errors can reach a language model through MCP.
   - **Messages:** every message names the file by its role (the store, the slide, the raster file, the scratch file, the journal) and never by its path. The files with known sites are:
     - `src/workspace/workspace.cpp` (17);
     - `src/storage/detail/store_impl.cpp` (14);
     - `src/storage/detail/file_io.cpp` (6), `tiff_io.cpp` (6), `tile_spool.cpp` (5), `tiff_raster_reader.cpp` (3), `writer_lock.cpp` (2), `sqlite.cpp` (1);
     - `src/storage/event_journal.cpp` (3), `geojson_import.cpp` (4), `object_cursor.cpp` (1);
     - `src/pipeline/detail/fragment_spill.cpp` (2).

     Find the rest with a search for messages concatenating a path or `u8string()`.
   - **Causes:**
     - from a `std::filesystem::filesystem_error`, the cause is `code().message()`, never `what()`, which contains the paths;
     - from SlideIO, the cause is SlideIO's text with every occurrence of the slide path, both as given and absolute, replaced by `<slide>`;
     - other causes are unchanged.
   - **Logs:** log lines follow the same rules. These include `store_impl.cpp`, `store.cpp`, `tiff_io.cpp` and `workspace.cpp`.
   - **What stays:** `Workspace::path()`, `slidePath()` and `Store::path()` still return their paths. Only diagnostic text changes.
   - **Enforcement:** a test-time check (decision 7's test) fails when a message or log line contains a known path.
8. **Docs.**
   - A new `docs/superpowers/specs/sds/09-run.md` covers decisions 4–5, the module's dependencies, and what batch processing adds later (design §8).
   - SDS 05 gains decisions 1–3, and SDS 04 the record key and `isDeterministic`.
   - The module-structure design gains the `run` module and its edges, and SDS 08 the new classes.
   - `docs/project.md` gains a "Python bindings project 1" entry with the follow-ups:
     - the `slideio-process` CLI over `SlideRun`;
     - the batch additions of design §8.
   - SDS 04 gains decision 6, and SDS 00 (conventions) gains decision 7's rule for messages, causes and logs.
   - `docs/traceability.md` lists every new test.

## Review Focus

1. **An object at the slide's edge** is complete, not truncated: a `LabelImageOperation` object touching the level's right or bottom edge is stored and not counted (`LabelImage.ObjectsAtTheLevelEdgeAreKept`, Task 3).
2. **Re-running an unchanged pipeline** runs no stage, and rewrites byte-identical CSV and GeoJSON (`SlideRun.SecondRunRunsNothing`, Task 5).
3. **Export names that escape the directory** (`../x.csv`, `C:x.csv`, `a/b.csv`, `a\b.csv`) are refused before anything runs (`PipelineFile.RefusesUnsafeExportNames`, Task 4).
4. **A workspace of another slide or scene** is refused, and its store is unchanged (`SlideRun.RefusesAWorkspaceOfAnotherSlide`, Task 5).
5. **A changed parameter** re-runs that stage and its dependents only, not unrelated stages (`SlideRun.ChangedParameterRerunsTheStageAndDependents`, Task 5).
