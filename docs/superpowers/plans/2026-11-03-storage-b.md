# `storage` Module Implementation Plan B: edges, annotations, import, primitive drop

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the second part of the `storage` module to `slideio-processor`. It covers parent and derived-from edges, label and measurement annotations, the effective-label raster source, primitive-layer drop and GeoJSON import. Along the way, the object query filters and `discardStage` learn about the new tables.

**Architecture:**
- **This is plan B of three.** Plan A (`2026-10-20-storage-a.md`) is merged. Plan C adds `RasterRegistry`.
- Plan B adds:
  - `EdgeStore`/`EdgeWriter` (§3.6) and `AnnotationStore`/`AnnotationWriter` (§3.7);
  - `GeoJsonImporter` and `importRoiPolygon` (§3.11);
  - `LayerRegistry::dropPrimitive` and its two companions;
  - a store-backed effective-label raster source;
  - the four tables `parent_edges`, `derived_from`, `label_assertions` and `measurement_assertions`.
- `Store` gains `edges()` and `annotations()`.
- **Every new mechanism reuses plan A's, by name:**
  - writes run in `detail::StoreImpl::withWriteTransaction`;
  - events are appended through `detail::appendEvent` and followed by `notifyCommitted()`;
  - writers are `detail::GateClient`s registered with `StoreGate::track`, so `Store::close()` flushes them. Their assert calls refuse through `checkAcceptingObjects`, exactly as `ObjectWriter::emit` does;
  - every batch follows `object_writer.cpp`'s pattern. A failed commit rolls back the whole batch, drops what was pending, and the call that triggered the commit throws (S8);
  - cursors hold a `ReadLease` from `acquireRead`, never a `StoreImpl&`. Object-record cursors are a hand-built `detail::BuiltQuery` run through `detail::openObjectCursor`.
- **The v1 format stays `format_version` 1.** B adds its tables and two `layers` columns to the creation DDL in `detail/schema.cpp`. A store written before plan C is a development artefact, and nothing migrates it.
- **Three decisions, made by the user before this plan was written, are binding.** Each is recorded as a ruling:
  - the effective-label raster (S15);
  - primitive drop (S16);
  - fixing the GeoJSON gaps in `core` (S17).

**Tech Stack:** C++17, CMake ≥ 3.21, Conan 2. `sqlite3/3.44.2`, `gtest/1.17.0` and `rapidjson/cci.20250205` are as in plan A. Nothing new.

**Spec:**
- `docs/superpowers/specs/sds/03-storage.md` (SDS 03): §3.6, §3.7, §3.11 and the B tables of §3.12, plus the `LayerRegistry` and `ObjectQuery` paragraphs of §3.3 and §3.5 that name plan B.
- `docs/superpowers/specs/sds/04-workspace.md` §4.6, for what `LayerLifecycle::drop` needs.
- `docs/superpowers/specs/sds/01-core.md` §1.9, §1.13 and §1.14.
- Requirements: `docs/requirements.md`. Plan A's rulings S1–S14 hold unchanged.

## Global Constraints

Every constraint of plan A ("Global Constraints") holds unchanged. In summary:
- C++17, in `namespace slideio::processor`, with private helpers in `slideio::processor::detail`.
- The export macro is `SLIDEIO_PROCESSOR_DATA_EXPORTS`.
- **ABI rules (C-2):** pimpl through `std::unique_ptr<Impl>`; every definition out of line; no STL container, `std::string` or template in a public signature except `std::shared_ptr`; every `enum class` is `: int32_t`.
- **Strings (C-4):** in, `const char*` UTF-8; paths go through `std::filesystem::u8path`.
- **Errors (C-6):** `std::bad_alloc` is the only non-`ProcessorError` that may cross the boundary. A SQLite failure becomes `IoError` naming the store path. A broken invariant becomes `InternalError`.
- **Moved-from rule (C-8), documentation (C-12),** and the `// Requirements: …` line at the top of every test file.
- **SQLite stays PRIVATE and OpenCV is never linked** (plan A).
- **Error text never copies file content beyond names.** Plan A's Task 3 ruling extends to import, because a GeoJSON property or provenance record may carry patient identifiers:
  - a diagnostic may name a label, a measurement name, a layer, an `ObjectId`, a feature index or a path;
  - it never names a property value or a provenance field.

| S17 | GeoJSON gaps (user decision 3), fixed in `core`. | `GeoJsonReader` gains three things.<br>**(a) Array-form measurements.** QuPath before 0.3 wrote `properties.measurements` as `[{"name": s, "value": v}, …]`. ## Review Focus

1. **Edges and annotations naming an object still pending in an unflushed `ObjectWriter`**, flushed before that writer. The flush must throw `InvalidArgumentError` naming the missing endpoint and roll the whole batch back. Flushing in the right order must then succeed (S19, S22). This is pinned in Tasks 3 and 4.
2. **An annotating stage still running while another stage queries `label(L)`, or a measurement bound.** Under `CompletedOnly` the query must not see the running annotator's assertions, and under `IncludeInFlight` it must (S24). This is pinned in Task 5.
3. **Re-running a producing stage (`discardStage`) that other stages have annotated, attached to and derived from.** No assertion or edge row may dangle. Former children must read as unattached, and the label raster must show no stale label (S25). This is pinned in Task 5.
4. **Dropping a primitive layer while an `ObjectWriter` holds pending objects for it.** The later commit must fail, naming the dropped layer, and nothing may reappear. Derived objects must stay visible and report no origins, and a second handle must see `isDropped` without reopening (S16, S28). This is pinned in Task 7.
5. **A QuPath file whose only unknown class is on its last feature, imported under `Strict`.** No object, no label and no event may be written. The same file under `Permissive` imports, with mixed-case aliases (`Tumor`) resolving to standard labels and pre-0.3 array-form measurements arriving (S17, S26). This is pinned in Task 8.
