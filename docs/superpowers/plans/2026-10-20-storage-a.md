# `storage` Module Implementation Plan A: store, layers, vocabulary, objects, journal

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first part of the `storage` module of `slideio-processor`: the SQLite store file, its full v1 schema, the layer and vocabulary registries, the object writer and object queries, stage state (read and write), and the event journal with its local wake-up signal. It ships inside `slideio-processor-data`, next to `core` and `config`.

**Architecture:**
- `storage` is a third OBJECT library, `slideio-processor-storage`, linked PRIVATE into the SHARED library `slideio-processor-data` the same way `core` and `config` are. It links SQLite PRIVATE.
- Layout:
  - public headers under `include/slideio/processor/storage/`;
  - sources under `src/storage/`, with private helpers in `src/storage/detail/`;
  - tests under `tests/storage/`, built as their own executable, plus a small helper executable for the cross-process tests.
- **This is plan A of three.** Plan B adds `EdgeStore`, `AnnotationStore`, `GeoJsonImporter`, primitive-layer drop, the effective-label raster source, and extends `discardStage` and the label and measurement query filters to the annotation tables. Plan C adds `RasterRegistry`. `Store` in this plan therefore declares only the accessors whose classes exist: `layers()`, `vocabulary()`, `objects()`, `events()`, `stageStates()` and `stageStateWriter()`. B and C add `edges()`, `annotations()` and `rasters()`.
- **The v1 format is not frozen until plan C lands.** Plan A creates the tables it fills (Task 3); B and C add theirs to the same creation DDL, and `format_version` stays 1 throughout. A store written before plan C is a development artefact, and nothing migrates it. Freezing the format earlier would mean designing B's and C's tables before their plans exist.
- **Three amendments, decided before this plan was written, are binding here:**
  - geometry is stored in a compact delta-varint encoding (S1), which resolves open question 5;
  - a public `StageStateWriter` is how `workspace` writes stage rows (S11);
  - two restoring factories are added to `core`, `ObjectRecord::restored` and `Provenance::restored` (Task 2).

**Tech Stack:**
- C++17, CMake ≥ 3.21 and Conan 2.
- `gtest/1.17.0`, `rapidjson/cci.20250205` and `opencv/4.14.0` (version only), as before.
- New: `sqlite3/3.44.2`, the version SlideIO's converter pins, with its R\*Tree module (UR-BLD-5).

**Spec:** `docs/superpowers/specs/sds/03-storage.md` (SDS 03) §3.1–3.5, §3.9, §3.10 and §3.12, under `docs/superpowers/specs/sds/00-conventions.md` (SDS 00). `core`'s contract is `docs/superpowers/specs/sds/01-core.md` and the headers in `include/slideio/processor/core/`. `config`'s is `docs/superpowers/specs/sds/02-config.md`. Requirement IDs refer to `docs/requirements.md` and, for UR-OBS-1..7, `docs/requirements-9a-observation-draft.md`, which this plan treats as binding.

## Rulings on spec gaps

SDS 03 leaves the following open. Each ruling binds this plan and is to be folded back into SDS 03 afterwards, the way SDS 01 and SDS 02 were.

| # | Gap | Ruling |
|---|---|---|
| S1 | Geometry encoding (open question 5). | One BLOB per object, private to the store and covered by the format version. Byte 0 is the encoding version, `1`. Then: a varint ring count; then, for each ring, a varint `(pointCount << 1) \| isHole`, followed by the points. The first point of each ring is stored as zigzag-varint absolute `x` and `y`. Each later point is stored as zigzag-varint deltas from the previous point, computed in wrapping `uint64_t` arithmetic, so every `int64_t` pair round-trips exactly. Varints are LEB128, unsigned, at most 10 bytes. A blob that is truncated, has trailing bytes, an unknown version, an over-long varint, or a ring of fewer than 3 points throws `InternalError` naming the object. |
| S2 | Store file and lifecycle. | `storeFormatVersion()` returns 1. `open` modes: `CreateNew` creates, and fails with `IoError` if the path exists. `ReadWrite` and `ReadOnly` require an existing file, and fail with `IoError` naming the path if it is missing. `mode()` returns the mode passed in; `isReadOnly()` is true only for `ReadOnly`. A file that is not a SQLite database, or has no `meta` table, throws `StoreFormatError` with store version 0. A `format_version` other than 1 throws `StoreFormatError(store, 1)`; the message names both versions. Every mutating call on a `ReadOnly` store throws `IoError` naming the path and the word `read-only`. After `close()`, every method except `path()`, `formatVersion()`, `mode()` and `isReadOnly()` throws `IoError` with `store is closed`. The destructor calls `close()`, logs any error at `Error`, and swallows it. |
| S3 | The exclusive writer lock (§3.2). | A lock file at `<path>-writer.lock`, holding the owner's process id as decimal text. It is locked with `LockFileEx` on Windows and `flock(LOCK_EX \| LOCK_NB)` on POSIX, and held until `close()`. A failed lock throws `IoError` naming the path and, when the file's text parses, `process <pid>`. A second `ReadWrite` open in the same process fails the same way, because both platforms lock per handle. `ReadOnly` takes no lock. |
| S4 | Connections and snapshots (§3.2). | WAL mode, `synchronous=NORMAL`, `foreign_keys=ON`, `busy_timeout=5000`. There is one write connection, guarded by a mutex; every write transaction runs on it. Read connections come from a pool; a point read checks one out for the call. A cursor (object or event) checks one out for its lifetime and holds one read transaction, so it sees a single snapshot and never a partially applied batch (UR-OBS-1). |
| S5 | Ids. | `pixelLayer()` is `LayerId(1)`, named `pixel`, kind Semantic, depth 0, parent invalid. It is created with the store. Declared layers number from 2 upward; stages from 1. **Workspace-local labels number from 65536 upward.** Ids 1..65535 are reserved for the standard vocabulary, so a later standard version can append ids without colliding with a local id already written. |
| S6 | Layer names. | Names are unique across all layers, compared exactly. A null or empty name, a duplicate, or `pixel` throws `InvalidArgumentError` naming it. `declareSemantic` requires an existing, semantic, undropped parent. `at`, `name`, `kind` and `parent` on an unknown id throw `InvalidArgumentError`. `isAbove` throws when either layer is primitive or unknown. `recordAnalysisLevel` takes the maximum, and throws for a negative level or an unknown layer. `coarsestAnalysisLevel` of an unknown layer is 0. `writerStageAt` lists `stage_layers` rows in ascending stage id. `isDropped` reads its column; nothing in plan A sets it (plan B adds the drop). |
| S7 | Vocabulary matching (§3.4). | `find` folds ASCII case and then consults the alias table: `tumor`→`tumour`, `artifact`→`artefact`, `immune cells`→`immune`, `ignore*`→`ignore`. A null or empty name returns false. `addLocal` returns the existing id when `find` already resolves the name (no row added, no event). Otherwise it inserts with origin `WorkspaceLocal` and appends `LabelAdded`. A null or empty name throws `InvalidArgumentError`. The ten standard rows are seeded at creation; the store's table is authoritative for `name()`. `recordedStandardVersion()` is fixed at creation. `isRecognised` is false for an id in 1..65535 above the library's `StandardVocabulary::labelCount()`. `importPolicy()` defaults to `Strict` and persists in `meta`. |
| S8 | Object validation and collisions (§3.5). | `emit` throws `InvalidArgumentError` for: an undeclared or dropped layer, or the pixel layer; empty geometry; an invalid `ObjectId` (anchor outside the packable range; the message names the anchor); a label the store does not hold; and an anchor already pending in the same writer's batch. A collision with a committed row is caught at commit by the `UNIQUE(layer_id, anchor_id)` index. The whole batch is then rolled back and its pending objects dropped, and the call that triggered the commit (`emit` or `flush`) throws `InvalidArgumentError` naming the layer and the anchor. `emittedCount()` counts accepted records, pending and committed. The destructor flushes, logs a failure at `Error`, and swallows it. `writerForStage` throws `InvalidArgumentError` for an unknown stage, and `IoError` on a `ReadOnly` store. `ObjectWriter`: `emit` is ThreadSafe; `flush` requires exclusive access, as for `EdgeWriter`. |
| S9 | Batch events. | A commit writes one `ObjectsAdded` row per distinct layer in the batch, in ascending layer id, each with that layer's count and union bounding box, in the same transaction as the rows. Objects are inserted in arrival order: SDS 03 §3.12 measured per-batch sorting at 18% slower. |
| S10 | Query semantics (§3.5). | Results are in ascending `ObjectId` order, `(layer_id, anchor_id)`, whatever the arrival order (UR-QA-3). `CompletedOnly` admits objects whose stage status is `Complete`, stale or not. `get` honours `CompletedOnly`: it is the default view, so UR-STG-5 holds for point reads too. An observer uses `query` with `IncludeInFlight`. The R\*Tree is SQLite's float `rtree`, which rounds outward. Every candidate is re-checked against the exact `int64` bounding box in `objects`, then against the polygon predicate in C++. Polygon filters and `limit` are applied in the cursor loop, after the exact checks. Measurement bounds match the producer's `measurements` table; an object lacking the name fails the bound. Label filters use the row label, which is the whole effective set until plan B adds `label_assertions`. No parent edge can exist until plan B either, so `AttachedOnly` matches nothing and `UnattachedOnly` matches everything. Plan B replaces both with real joins. `totalObjectCount` and `objectCountInLayer` count every stored row, whatever the visibility. `Cursor::position()` is the zero-based index of the current record. |
| S11 | Stage writes (decided). | A new class `StageStateWriter`, returned by `Store::stageStateWriter()`. See Task 5 for its signatures. A status change appends `StageStateChanged` in the same transaction. Entering `Complete` sets `completedAtUnixMs` to now; no other transition changes it. Stage names are unique and compared exactly. |
| S12 | Journal positions (§3.9). | Sequences start at 1 and are never reused (`AUTOINCREMENT`). `kFromBeginning` is -1, and `kFromNow` is -2. `newestSequence()` is the last sequence ever assigned, or 0. `oldestSequence()` is the smallest retained sequence, or `newestSequence() + 1` when none are retained. `truncateBelow(s)` deletes `seq < s` and records `s` as the watermark in `meta`. `subscribe(f)` for `f >= 0` throws `InvalidArgumentError` naming `f` and the watermark when `f + 1 < watermark`. Any other negative `f` throws. `next(t)` with `t < -1` throws. A cursor's `position()` is the sequence last returned, or the resolved start before the first `next()`. Events for a non-batch kind carry an empty bounding box and a count of 0. `StageDiscarded` carries the number of objects removed. |
| S13 | Wake-up signal (§3.9, UR-OBS-6). | The signal is named from a random 128-bit `store_uuid` in `meta`, written at creation, never from the path. **Windows:** a manual-reset named event, `Local\slideio-processor-<uuid>`. The writer sets it after every commit that appends an event; a waiter resets it after waking. **Linux:** a POSIX named semaphore, `/slideio-processor-<uuid>`, mode 0600, posted after every such commit; waiters use `sem_timedwait` and drain with `sem_trywait`. **macOS:** no signal. `sem_timedwait` does not exist there, so subscribers poll at `eventPollIntervalMs`. A wait never exceeds the poll interval, so a missed signal costs at most one interval. |
| S14 | Provenance (§3.2). | `meta.provenance` holds `Provenance::toJson`. It is written at creation from a default `Provenance()`, so it holds the creating library's version and the creation time. `provenance()` parses it (RapidJSON, in `detail`) and returns `Provenance::restored(...)`, so the version and time are the stored ones. `setProvenance` replaces it. |

## Review Focus

1. **Two objects in one layer sharing an anchor:** in one batch, across two batches of one writer, and across two stages. Each must throw `InvalidArgumentError` naming the layer and the anchor, and leave no partial batch committed (S8). This is pinned in Task 7.
2. **A cursor held open while the writer commits more batches.** It must return exactly its snapshot's objects, with no duplicates and none missing (S4, UR-OBS-1). This is pinned in Task 8.
3. **Another process reading, and subscribing, while this one writes.** No `SQLITE_BUSY` may surface as an error on either side, and the reader must see each batch whole or not at all. This is pinned in Task 9.
4. **Coordinates beyond float32 precision,** such as x near 2³¹−1 and y near 2³²−1, in a spatial query. There must be no false negatives: the float R\*Tree rounds outward, and the exact recheck removes the false positives (S10). This is pinned in Task 8.
5. **A store path with non-ASCII characters** (`ü_日本.store`) on Windows. Open, the writer lock file, close and reopen must all work. This is pinned in Task 3.
